# Plan: IAM — пользователи, сессии и JWT

**PRD:** [prd-iam-authentication.md](prd-iam-authentication.md)
**Дата:** 2026-11-08

## Фазы реализации

### Фаза 1: Регистрация и вход по сессии (Tracer Bullet) — выполнена

**Цель:** Пользователь регистрируется и получает сессию.
**Затрагивает:** backend, database
**Задачи:**

- [x] Миграции `users`, `notification_methods`, `sessions`
- [x] `Register`, `GetUser` с хешированием пароля
- [x] `Login`, `Whoami`, `Logout`
- [x] Unit-тесты сервисов и репозитория

**Когда готова:** вход по верному паролю даёт сессию, по неверному — ошибку.

### Фаза 2: JWT и отзыв токенов — выполнена

**Цель:** Stateless-аутентификация для сервисов.
**Затрагивает:** backend
**Задачи:**

- [x] `JWTLogin`, access/refresh токены с TTL из конфига
- [x] `GetAccessToken`, `GetRefreshToken`
- [x] `RevokeToken`, `RevokeAllUserTokens` (см. [plan-iam-redis-session-cache.md](plan-iam-redis-session-cache.md))
- [x] Middleware проверки токена

**Когда готова:** отозванный токен отклоняется.

### Фаза 3: Защита от перебора

**Цель:** Ограничить попытки входа.
**Затрагивает:** backend
**Задачи:**

- [x] Тесты блокировки после N неудачных попыток
- [x] Ограничение частоты попыток входа (уже было: 5 попыток в минуту на IP; BFF теперь передаёт IP клиента)

**Когда готова:** (N+1)-я попытка за окно времени отклоняется до истечения блокировки.
