# Plan: Каталог деталей (inventory)

**PRD:** [prd-inventory-catalog.md](prd-inventory-catalog.md)
**Дата:** 2026-11-08

## Фазы реализации

### Фаза 1: Получение детали (Tracer Bullet) — выполнена

**Цель:** `order` получает деталь по UUID.
**Затрагивает:** backend, database
**Задачи:**

- [x] Контракт `InventoryService` и генерация
- [x] `GetPart`, репозитории MongoDB и in-memory
- [x] Unit-тесты

**Когда готова:** несуществующий UUID даёт ошибку «не найдена».

### Фаза 2: Список с фильтром — выполнена

**Цель:** Подбор деталей по фильтру.
**Затрагивает:** backend
**Задачи:**

- [x] `ListParts` с фильтром по UUID, названиям, категориям, странам, тегам
- [x] Категории `ENGINE`, `FUEL`, `PORTHOLE`, `WING`
- [x] Unit- и интеграционные тесты (`inventory/tests/integration`)

**Когда готова:** каждый фильтр проверен тестом.

### Фаза 3: Остатки деталей

**Цель:** Не принимать заказ на детали, которых нет в наличии.
**Затрагивает:** backend, database
**Задачи:**

- [x] Тесты учёта и резервирования остатков
- [x] Учёт остатков деталей в модели и репозитории

**Когда готова:** заказ на деталь с нулевым остатком отклоняется (409). Резерв списывает остаток при создании заказа и возвращается при отмене; логика проверена на реальной MongoDB (`go test -tags=integration ./inventory/internal/repository/mongo/`).
