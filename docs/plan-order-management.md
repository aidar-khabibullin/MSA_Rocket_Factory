# Plan: Заказы — создание, оплата, отмена

**PRD:** [prd-order-management.md](prd-order-management.md)
**Дата:** 2026-11-08

## Фазы реализации

### Фаза 1: Создание и чтение заказа (Tracer Bullet) — выполнена

**Цель:** Клиент создаёт заказ и видит его.
**Затрагивает:** backend, database
**Задачи:**

- [x] OpenAPI-контракт и генерация (`task ogen:gen`)
- [x] `CreateOrder` с валидацией и запросом деталей у `inventory`
- [x] `GetOrder`, репозиторий PostgreSQL и миграция
- [x] Unit-тесты сервиса

**Когда готова:** `POST` и `GET` возвращают заказ в `PENDING_PAYMENT`.

### Фаза 2: Оплата и событие — выполнена

**Цель:** Оплаченный заказ запускает сборку.
**Затрагивает:** backend
**Задачи:**

- [x] `PayOrder` с вызовом `payment` и условной записью статуса
- [x] Публикация `order.paid` (`acks=all`)
- [x] Consumer `ship.assembled` -> `ASSEMBLED`
- [x] Unit- и интеграционные тесты

**Когда готова:** из двух параллельных оплат только одна даёт `PAID`.

### Фаза 3: Отмена, метрики, нагрузка — выполнена

**Цель:** Завершить жизненный цикл заказа и наблюдаемость.
**Затрагивает:** backend, docs
**Задачи:**

- [x] `CancelOrder` (запрет для `PAID`/`ASSEMBLED`)
- [x] Метрики и трассировка
- [x] Нагрузочный тест и [load-testing.md](load-testing.md)

**Когда готова:** отмена оплаченного заказа отклоняется.

### Фаза 4: Полная идемпотентность оплаты

**Цель:** Закрыть гонку при параллельной оплате.
**Затрагивает:** backend (`order`, `payment`)
**Задачи:**

- [x] Тест: параллельные оплаты вызывают `payment` один раз
- [x] Идемпотентный ключ платежа (см. [plan-payment-processing.md](plan-payment-processing.md))
- [x] Условный `UpdateOrderStatus` — в [plan-reliable-kafka-event-delivery.md](plan-reliable-kafka-event-delivery.md), фаза 2

**Когда готова:** проигравший запрос не обращается к `payment`.
