## Фазы реализации

### Фаза 1: Имитация оплаты (Tracer Bullet) — выполнена

**Цель:** `order` получает UUID транзакции.
**Затрагивает:** backend
**Задачи:**

- [x] Контракт `PaymentService.PayOrder` и HTTP-шлюз
- [x] Сервис: генерация UUID транзакции, трассировка, логи
- [x] Unit-тесты сервиса и API

**Когда готова:** `PayOrder` возвращает непустой UUID.

### Фаза 2: Идемпотентность и возвраты

**Цель:** Безопасные повторы и компенсация.
**Затрагивает:** backend
**Задачи:**

- [x] Тесты: повторный вызов с тем же ключом возвращает ту же транзакцию
- [x] Идемпотентный ключ платежа
- [x] Метод возврата платежа для компенсации

**Когда готова:** два вызова с одним `order_uuid` дают один `transaction_uuid` (ключом идемпотентности служит `order_uuid`, отдельное поле не нужно). Компенсация в `order`: если после оплаты заказ не удалось обновить, платёж возвращается.
