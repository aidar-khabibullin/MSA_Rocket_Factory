# PRD: IAM — пользователи, сессии и JWT

**Дата**: 2026-11-08
**Статус**: Implemented

## Цель

Дать остальным сервисам единый способ зарегистрировать пользователя, проверить его личность и понять, кто делает запрос. Пользователь входит один раз и дальше работает по сессии или JWT.

## Пользовательские сценарии

- Пользователь регистрируется с логином и паролем -> создаётся учётная запись, пароль хранится только в виде хеша.
- Пользователь входит по логину и паролю -> получает сессию (`Login`) или пару access/refresh JWT (`JWTLogin`).
- Сервис проверяет сессию (`Whoami`) -> получает сессию и данные пользователя.
- Пользователь выходит (`Logout`) -> сессия перестаёт действовать.
- Клиент обменивает refresh-токен (`GetAccessToken`, `GetRefreshToken`) -> получает новые токены.
- Токен отзывается (`RevokeToken`, `RevokeAllUserTokens`) -> он больше не принимается.
- `notification` запрашивает пользователя (`GetUser`) -> получает его способы оповещения, в том числе Telegram.

## В скоупе

- gRPC `UserService` (`Register`, `GetUser`), `AuthService` (`Login`, `Whoami`), `JWTService` (`Login`, `GetAccessToken`, `GetRefreshToken`) — `shared/proto/iam`, `shared/proto/jwt`.
- Хранение в PostgreSQL: таблицы `users`, `notification_methods`, `sessions` (миграции `iam/migrations`).
- Хеширование паролей; проверка пароля с выравниванием времени ответа при неизвестном логине (`burnPasswordCheck`).
- TTL токенов из конфигурации: access 15 минут, refresh 24 часа (по умолчанию).
- Отзыв токенов (одного и всех токенов пользователя), см. [prd-iam-redis-session-cache.md](prd-iam-redis-session-cache.md).
- Middleware проверки токена в `iam/internal/middleware`.

## Не в скоупе

- Роли и права доступа (RBAC).
- Восстановление пароля, подтверждение email, 2FA.
- OAuth и внешние провайдеры.
- Ограничение частоты попыток входа (rate limiting).

## Технические ограничения

- Пароль не возвращается ни в одном ответе и не пишется в логи.
- Сессии и чёрный список токенов живут в Redis; при его недоступности поведение определяется `composite`-репозиторием.
- Секреты и TTL задаются через переменные окружения (`JWT_ACCESS_TOKEN_TTL`, `JWT_REFRESH_TOKEN_TTL`).

## Критерии готовности

- [x] `Register` создаёт пользователя, повторная регистрация того же логина отклоняется.
- [x] `Login` с верным паролем возвращает сессию, с неверным — ошибку аутентификации.
- [x] `JWTLogin` возвращает пару токенов с заданными TTL.
- [x] Refresh-токен обменивается на новые токены, отозванный токен отклоняется.
- [x] `Logout` и `RevokeAllUserTokens` делают сессии и токены недействительными.
- [x] Unit-тесты сервисов и репозиториев; покрытие сервиса и репозитория 73%.
- [x] Ограничение частоты попыток входа (добавить, если сервис станет публичным).
