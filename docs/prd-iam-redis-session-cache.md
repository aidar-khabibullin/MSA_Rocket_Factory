# PRD: Redis — кеш сессий и чёрный список токенов IAM

**Дата**: 2026-11-08
**Статус**: Implemented

## Цель

Проверять сессии и токены без обращения к PostgreSQL на каждый запрос и мгновенно отзывать токены, не дожидаясь их истечения.

## Пользовательские сценарии

- Сервис проверяет сессию повторно -> ответ берётся из Redis (cache hit), PostgreSQL не нагружается.
- Сессии нет в Redis -> она читается из PostgreSQL и кладётся в кеш (cache miss).
- Пользователь выходит -> сессия удаляется из кеша и больше не проходит проверку.
- Администратор отзывает токен или все токены пользователя -> токены, выпущенные до отзыва, отклоняются.
- Оператор смотрит статистику кеша -> видит hit/miss и hit ratio.

## В скоупе

- Репозиторий сессий в Redis (`iam/internal/repository/redis`) и composite-репозиторий (Redis + PostgreSQL).
- `CacheManager`: `GetSession`, `SetSession`, `DeleteSession`, статистика (`GetStats`, `GetHitRatio`, `LogStats`, `ResetStats`), прогрев (`WarmupCache`).
- `TokenBlacklistService`: отзыв одного токена, отзыв всех токенов пользователя, проверка отзыва (`IsTokenRevoked`, `IsUserTokensRevoked`).
- Все ключи в Redis имеют TTL (`Set` всегда задаёт срок жизни).
- Подключение к Redis через общий пакет `platform/pkg/cache`; таймауты задаются в конфигурации (`REDIS_CONNECTION_TIMEOUT`, `REDIS_IDLE_TIMEOUT`).

## Не в скоупе

- Redis Cluster и Sentinel.
- Использование Redis для дедупликации Kafka-событий — см. [prd-reliable-kafka-event-delivery.md](prd-reliable-kafka-event-delivery.md).
- Кеширование данных `order` и `inventory`.

## Технические ограничения

- TTL записи в кеше не должен превышать срок жизни сессии или токена.
- Чёрный список хранит запись только до истечения самого токена.
- Кеш — оптимизация: источником истины для сессий остаётся PostgreSQL.

## Критерии готовности

- [x] Повторный `GetSession` не обращается к PostgreSQL.
- [x] После `DeleteSession` сессия не возвращается из кеша.
- [x] Отозванный токен отклоняется; токены, выпущенные до `RevokeAllUserTokens`, отклоняются, выпущенные после — принимаются.
- [x] Все ключи создаются с TTL.
- [x] `GetHitRatio` возвращает долю попаданий по накопленной статистике.
- [x] Unit-тесты менеджера кеша и чёрного списка.
- [x] Интеграционный тест с реальным Redis (testcontainers) для Redis-репозитория сессий (`iam/internal/repository/redis`). Composite-репозиторий на реальных базах не проверялся.
