# PRD: Каталог деталей (inventory)

**Дата**: 2026-11-08
**Статус**: Implemented

## Цель

Хранить каталог деталей для ракет и отдавать его сервису заказов по gRPC, чтобы заказ собирался только из существующих деталей.

## Пользовательские сценарии

- `order` запрашивает деталь по UUID (`GetPart`) -> получает её данные или ошибку «не найдена».
- `order` запрашивает список деталей с фильтром (`ListParts`) -> получает подходящие детали.
- Клиент собирает заказ из деталей определённых категорий (двигатель, топливо, иллюминатор, крыло) -> детали находятся по фильтру.

## В скоупе

- gRPC `InventoryService`: `GetPart`, `ListParts` (`shared/proto/inventory`, порт `:50051`).
- Фильтр `ListParts` по UUID, названиям, категориям, странам производителей и тегам.
- `ReserveParts` и `ReleaseParts`: атомарное и идемпотентное по заказу резервирование остатков; при нехватке хотя бы одной детали не резервируется ничего, `order` отвечает 409.
- Категории: `ENGINE`, `FUEL`, `PORTHOLE`, `WING`; неизвестное значение отображается как `UNKNOWN`.
- Хранение в MongoDB; in-memory репозиторий для тестов.
- Health-check, трассировка и метрики gRPC.

## Не в скоупе

- Создание, редактирование и удаление деталей через API (кроме резервирования под заказ).
- Цены и валюты на стороне `inventory` сверх того, что хранится в модели детали.

## Технические ограничения

- Каталог только читается через gRPC; наполнение происходит вне API сервиса.
- Фильтр с пустыми полями возвращает весь каталог.

## Критерии готовности

- [x] `GetPart` возвращает деталь по UUID; несуществующий UUID даёт ошибку «не найдена».
- [x] `ListParts` применяет фильтр по каждому из пяти полей.
- [x] Unit-тесты сервиса и репозитория, интеграционные тесты (`inventory/tests/integration`).
- [x] Категории покрыты тестами `Category.String` и `ToCategory`.
- [x] Учёт остатков деталей (если понадобится резервирование под заказ).
