# PRD: Заказы — создание, оплата, отмена

**Дата**: 2026-11-08
**Статус**: Implemented

## Цель

Дать клиенту HTTP API, через которое он собирает заказ из деталей каталога, оплачивает его и отслеживает статус до готовности ракеты.

## Пользовательские сценарии

- Клиент создаёт заказ с набором деталей -> заказ создан в статусе `PENDING_PAYMENT`.
- Клиент оплачивает заказ -> `payment` проводит платёж, заказ получает статус `PAID`, публикуется событие `order.paid`.
- Ракета собрана -> по событию `ship.assembled` заказ получает статус `ASSEMBLED`.
- Клиент запрашивает заказ -> видит текущий статус.
- Клиент отменяет неоплаченный заказ -> заказ получает статус `CANCELLED`.
- Клиент пытается оплатить заказ повторно или отменить оплаченный/собранный -> получает отказ, деньги не списываются второй раз.

## В скоупе

- HTTP API (OpenAPI, `backend/shared/api/order/v1`): `POST /api/v1/orders`, `GET /api/v1/orders/{order_uuid}`, `POST /api/v1/orders/{order_uuid}/pay`, `POST /api/v1/orders/{order_uuid}/cancel`.
- Валидация создания: пользователь указан, список деталей не пуст и не больше 1000; детали запрашиваются у `inventory` (gRPC).
- Оплата через `payment` (gRPC); запись результата условная: `UPDATE ... WHERE status = 'PENDING_PAYMENT'`.
- Публикация `order.paid` в Kafka (`acks=all`, 3 повтора отправки).
- Потребление `ship.assembled` и перевод заказа в `ASSEMBLED`.
- Хранение в PostgreSQL (`backend/order/migrations`), in-memory репозиторий для тестов.
- Health-check, трассировка (OpenTelemetry), бизнес-метрики заказов (см. [metrics.md](metrics.md)).

## Не в скоупе

- Корзина, скидки, доставка, возвраты.
- Редактирование заказа после создания.
- Надёжность доставки событий — см. [prd-reliable-kafka-event-delivery.md](prd-reliable-kafka-event-delivery.md).
- Transactional outbox и saga с компенсацией платежа.

## Технические ограничения

- Система eventually consistent: между оплатой и `ASSEMBLED` заказ находится в статусе `PAID`.
- Вызов `payment` происходит до записи статуса; гонка при параллельной оплате закрыта частично (см. `architecture.md`, п. 5).
- Запись в БД и публикация в Kafka не атомарны (`architecture.md`, п. 1).

## Критерии готовности

- [x] Оплата допустима только из `PENDING_PAYMENT`, иначе `ErrOrderNotPayable`.
- [x] Из двух параллельных оплат статус `PAID` и событие `order.paid` получает только одна.
- [x] Отмена `PAID` и `ASSEMBLED` заказа запрещена.
- [x] Событие `ship.assembled` переводит заказ в `ASSEMBLED`.
- [x] Unit-тесты сервиса, интеграционные тесты (`order/tests/integration`), нагрузочный тест ([load-testing.md](load-testing.md)).
- [x] Идемпотентный ключ платежа, закрывающий гонку полностью.
- [x] Условное обновление статуса в `UpdateOrderStatus` (входит в PRD доставки Kafka).
