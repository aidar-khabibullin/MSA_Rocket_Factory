# PRD: Сборка ракеты (assembly)

**Дата**: 2026-11-08
**Статус**: Implemented

## Цель

Собирать ракету асинхронно после оплаты, чтобы HTTP-запрос на оплату не ждал долгую операцию, и сообщать о готовности остальным сервисам.

## Пользовательские сценарии

- Заказ оплачен (`order.paid`) -> `assembly` собирает ракету.
- Сборка завершена -> публикуется `ship.assembled` с временем сборки, заказ получает `ASSEMBLED`, пользователь получает уведомление.
- Сервис остановлен во время сборки -> операция прерывается по отмене контекста, ошибка фиксируется в метриках.

## В скоупе

- Consumer `order.paid` в группе `assembly-service`.
- Имитация сборки: задержка 5–15 секунд, прерываемая отменой контекста.
- Producer `ship.assembled` с `order_uuid`, `user_uuid`, `build_time`.
- Метрики: начало, завершение, ошибки (`context_cancelled`, `producer_error`), длительность сборки.
- Health-check.

## Не в скоупе

- Реальная логика сборки и учёт деталей.
- Параллельная сборка нескольких заказов внутри одного consumer.
- Повторы, DLQ и дедупликация — см. [prd-reliable-kafka-event-delivery.md](prd-reliable-kafka-event-delivery.md).

## Технические ограничения

- Сборка выполняется в обработчике consumer, поэтому одна партиция обрабатывает около одного заказа в 10 секунд; масштабирование — партициями и репликами (`architecture.md`, п. 9).
- Повторная доставка `order.paid` приводит к повторной сборке (`architecture.md`, п. 4).

## Критерии готовности

- [x] Для каждого `order.paid` публикуется один `ship.assembled` с тем же `order_uuid`.
- [x] Время сборки лежит в диапазоне 5–15 секунд и передаётся в событии.
- [x] Отмена контекста прерывает сборку и записывает метрику ошибки.
- [x] Unit-тесты сервиса, consumer и producer.
- [x] Повторная доставка `order.paid` не вызывает повторную сборку.
